# User Testing Script — Grade 11/12 Students

## Setup
Use `/demo` (Try Demo Student) so participants don't need to create an account or enter real grades unless they want to. Sit beside them or screen-share; take notes verbatim where possible, especially confusion.

## Script
1. "Open Pathfinder. Before clicking anything, what do you think this website does?"
2. "Enter your actual courses and grades — or a fictional profile if you'd rather not share real ones."
3. "Find a program you're interested in and save it as a target."
4. "Look at this eligibility result. In your own words, what does it mean?"
5. "Based on that, what would you do next?"
6. "Try changing a grade or adding a course in the what-if simulator. What changed?"
7. "Did anything on this screen surprise you?"
8. "Which part of this would you actually come back and use again?"
9. "If this had a paid version, what would you expect to pay for?"
10. "Was there anything here you didn't trust, or weren't sure you could trust?"
11. "Can you point to the difference between an official requirement and Pathfinder's own advice on this page?"

## What to record per session
- Verbatim first-impression answer to Q1 (activation signal).
- Whether they understood "official requirement" vs. "strategic suggestion" without prompting (trust signal — see `docs/PRODUCT.md` rule 3).
- Every point of confusion, in their words, with the screen/step it happened on.
- Whether the what-if simulator result matched their expectation.
- Willingness-to-pay signal (open-ended, don't lead them toward a number).
- Any language that felt like a guarantee of admission, even if unintended by the copy — treat as a bug (`CLAUDE.md` rule: never imply admission is guaranteed).

## Do not run Phase 2 work off this feedback alone
Per `docs/MVP_TASKS.md`: don't expand scope based on fewer than ~20 real target users' sessions. Aggregate findings first.
